# Platform Web 使用指南

> 面向平台运营、平台管理员。  
> 本文只描述用户能做什么，不描述核心撮合内部实现。

## 1. 产品定位

Platform Web 是整个平台的管理入口，负责“平台级”能力，不是交易终端。

主要使用者：

- 平台管理员；
- 平台运营；
- 运维 / 审核人员。

## 2. 核心功能

### 租户申请与审核

平台可以查看租户申请并执行：

- 审核；
- 通过；
- 拒绝；
- 修改租户状态。

审核通过后由平台生成唯一 `location`，用户申请时不需要自己填写。

### Location 与集群路由

平台可以：

- 查看租户当前 location；
- 查看租户绑定的 Order / Trade / MD 逻辑集群；
- 使用系统默认路由；
- 在需要时调整集群分配。

### 租户管理

平台可以查看和维护：

- 租户基本资料；
- 状态；
- location；
- 路由；
- 配置；
- 使用情况。

### 系统管理

Platform Web 可以承载：

- 平台配置；
- 服务状态；
- 管理操作；
- 审计信息；
- 系统级查询。

## 3. 与其它 Web 的关系

```text
Platform Web
  └─ 管整个平台与全部租户

Tenant Web
  └─ 某一个租户 / Broker 自己的管理

Trade Web
  └─ 普通 Trader 的专业交易终端
```

Platform Web 不应复制 Trade Web 的专业交易功能，也不应把租户自己的客户管理功能全部塞进平台端。

## 4. 权限边界

平台管理员可以看平台级数据，但租户日常业务仍按 `location` 隔离。

任何平台操作都不应绕过后端权限验证，仅依赖前端隐藏按钮是不够的。

## 5. 文档与验收要求

生产验收至少覆盖：

- 管理员登录；
- 租户申请审核；
- location 生成；
- 路由分配；
- 租户状态修改；
- 页面与 Tenant / Trade Web 风格一致；
- 错误提示与权限控制；
- Desktop 实际页面截图。

## 6. 导航

Platform Web 需要能明确区分：

- 平台管理；
- 租户管理；
- 系统管理；
- 开发者 / API 文档入口。

不要把专业交易页面作为平台管理的默认主页面。
