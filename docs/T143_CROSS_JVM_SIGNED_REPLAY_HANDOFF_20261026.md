# T143 Common certified cross-JVM recovery handoff — 2026-10-26

## Actual code added

- `CommonDurableBusinessReplayHandoff` (Common, not Order/Trade): on EACH prospective READY admission, including the checks before business Netty binds, reopens the fsync'ed original `DurableRecoveryInstallLedger` from the NEW process, demands `REPLAY_COMPLETE` for EVERY physically assigned local partition with matching current Epoch/head, and calls the original source and loaded domain state verifier. It refuses a missing/unfinished/corrupt ledger or source Epoch beyond authenticated current assignment. It checks the ledger a SECOND time after cryptographic verification so a concurrent new INSTALLING transaction cannot silently replace it while being certified. This class **never** signs a new cert, CASes ZK, or grants business READY by itself.
- `CommonSignedReplayHandoffProof`: resolves old physical voter identities from a signed previous ZK membership (NOT from ledger properties), obtains Common `PhysicalVerifier.requireCertifiedWalCommitIndex` AND independently signed `requireDualSignedCustody` and requires exact partition/epoch/HEAD/hash and two separate original physical hosts. Then delegates to the business-loaded-state readback attestor for the exact recovered baseline + replayed committed head. Original signed recovery AND loaded live Order/Trade state BOTH must be verified again after restart. Default callbacks are NEVER success stubs.
- Order/Trade two new *optional* `*CommonDurableHandoffWiring` classes: enabled ONLY when `order.common.durableHandoff.enabled=true` or `trade.common.durableHandoff.enabled=true` is explicitly set. Default remains unchanged/fail-closed; when enabled, Spring requires original signed voter resolver and domain state attestor Beans, the real physical verifier and an existing durable recovery ledger directory. Without these real Bean providers, Spring startup FAILS (tested). `@Primary CommonBusinessRecoveryReadiness` routes official READY Netty and business admission through this Common verifier while preserving the original in-process `CommonCertifiedBusinessReplayGate` used by service recovery callbacks. Neither Order nor Trade adds ZK election, WAL, or replication logic.
