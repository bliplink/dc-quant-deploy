# DC SaaS 加密货币交易系统用户手册

本文适用于 `saas-crypto` 独立系统。当前验证环境为：

- Web：`http://172.16.97.64:18088/`
- 业务数据：MySQL
- 行情与 K 线：ClickHouse
- 租户标识：`location`

> 当前版本用于功能验证和后续产品化开发，不应接入真实资金。页面“充值”是测试环境内部记账，不是链上充值。

## 当前验收状态（2026-08-27）

已在 97.64 环境使用两个独立浏览器会话完成 `WEB_E2E` 租户闭环：用户名密码登录、测试入金、限价挂单、撤单、买卖双方撮合、成交历史和最近成交。成交用例为 `BTCUSDT`、价格 `60000`、数量 `0.001`；MySQL 中买卖订单均为 `Filled`、成交数量均为 `0.001`，并分别生成成交、手续费和资金流水记录。

本次验证还确认：浏览器修改请求中的用户或 `location` 不能替代已登录身份；Web 会从登录地址保留租户标识。该结论只代表当前已覆盖链路，不代表系统已经满足真实资金、安全合规或交易所级风险要求。

## 1. 登录

1. 从运营人员处取得用户名、密码和所属 `location`。
2. 打开租户登录地址：

   ```text
   http://172.16.97.64:18088/#/login?location=<你的 location>
   ```
3. 输入用户名和密码后单击“登录”。
4. 登录成功后进入交易页。租户专用地址格式为：

   ```text
   http://172.16.97.64:18088/#/trade?location=<你的 location>
   ```

不要修改或省略运营人员提供的 `location`。订单、成交、持仓、余额、资金流水、行情订阅和服务端查询都以它作为租户边界。

当前版本没有开放自助注册、找回密码、二次验证或 KYC；账户由运营人员创建。

## 2. 交易页布局

- 顶部：当前交易对、24 小时行情、标记价格、指数价格和资金费率。
- 左侧主区：K 线图、盘口和最近成交。
- 右侧：账户余额、充值/提现和下单面板。
- 底部：持仓、活动委托、委托历史、成交历史和资金流水。

默认交易对为 `BTCUSDT`。点击左上角交易对可打开 Markets 列表并切换交易对。

## 3. 添加测试资金

1. 在 `Account Info` 区域单击 `Deposit`。
2. 输入 USDT 数量。
3. 单击 `Confirm Deposit`。
4. 检查 `Total` 和 `Available` 是否增加。
5. 打开底部 `Funds` 页签，确认出现类型为 Deposit 的资金流水。

余额字段含义：

- `Total`：账户权益；当前余额加未实现盈亏。
- `Available`：可下单或提现的可用余额。
- `Position Margin`：持仓占用保证金。
- `Order Margin`：活动委托冻结的保证金和手续费。
- `Frozen`：其他冻结资金。
- `Unrealised PNL`：持仓未实现盈亏。

## 4. 下单

下单前确认交易对、方向、价格、数量和 `location` 均正确。

### 4.1 限价单

1. 在 `Place Order` 中选择 `Limit`。
2. 输入 `Limit Price`。
3. 输入 `Amount`。
4. 做多单击 `Buy/Long`，做空单击 `Sell/Short`。
5. 未立即成交的订单会显示在 `Open Orders`。

系统按价格优先、同价时间优先进行撮合。买价达到或高于卖价时可以成交，实际成交价由撮合簿中的挂单决定。

### 4.2 市价单

1. 选择 `Market`。
2. 输入 `Amount`。
3. 选择 `Buy/Long` 或 `Sell/Short`。

市价单依赖有效盘口和行情。97.64 当前不能访问 Binance 外部行情，因此没有有效盘口时不要使用市价单；恢复行情网络并完成滑点保护前，市价单不作为生产可用功能。

### 4.3 条件限价单

1. 选择 `Limit Conditional`。
2. 输入触发价和数量。
3. 选择 `Last Price` 或 `Mark Price` 作为触发源。
4. 选择买入或卖出。

当前条件单能力尚未达到 Binance/Bybit 的完整 TP/SL、追踪止损和 `reduceOnly` 语义，生产使用前必须按路线图补齐。

## 5. 撤单

1. 打开底部 `Open Orders`。
2. 找到目标交易对和订单。
3. 单击该行右侧 `Cancel`。
4. 撤单成功后，该订单从活动委托中消失，并在 `Order History` 中显示最终状态。

如果订单在撤单请求到达前已经完全成交，撤单可能被拒绝；应以成交回报和最终订单状态为准。

## 6. 查看成交和最近成交

- `Trade History`：仅显示当前用户的成交回报，包括数量、成交价、手续费、实现盈亏、订单号和成交号。
- `Order History`：显示订单完整生命周期，包括 `New`、`Partially_Filled`、`Filled`、`Canceled` 或拒单状态。
- `Recent Trades`：显示当前 `location`、当前交易对的市场最近成交，不是单个用户的私有成交记录。
- `Positions`：显示当前持仓、开仓均价、标记价格、保证金、强平价和盈亏。

常见状态：

- `Newing`：订单正在受理。
- `New`：订单已进入活动委托。
- `Partially_Filled`：部分成交，仍有剩余数量。
- `Filled`：全部成交。
- `Pending_Cancel`：撤单处理中。
- `Canceled`：已撤销。
- `Rejected`：订单校验或风险检查未通过；查看拒绝原因。

## 7. 当前限制

- 仅适合测试资金，尚未接入托管钱包、链上确认、提现审核和冷热钱包。
- 97.64 当前无法访问 Binance Futures，实时外部行情会持续重连。
- 为验证隔离撮合，97.64 显式启用了“缺少外部标记价时以限价作为临时校验价”的测试开关；生产默认关闭，接入可靠指数/标记价格后必须关闭该开关。
- 交易对精度、最小名义金额、价格保护、完整 TIF、STP、仓位模式和保证金规则尚未全部对标 Binance/Bybit。
- 当前为单机 Docker 部署，没有达到真实资金要求的多可用区、高可用和灾备等级。
- 页面部分历史中文资源存在编码问题；交易操作暂以英文按钮为准。

## 8. 使用安全

- 不要共享密码、会话令牌或未来创建的 API 密钥。
- 不要在公共电脑选择记住密码。
- 确认网址、`location` 和交易对后再操作。
- 遇到余额、订单或成交不一致时停止继续下单，记录订单号、成交号、时间和 `location`，由运营人员按 MySQL 订单/账本和服务日志核对。
