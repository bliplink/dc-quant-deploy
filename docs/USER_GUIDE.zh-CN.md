# DC SaaS 加密货币交易系统用户手册

本文适用于当前独立 SaaS 基线（2026-09-19）。系统与量化部署隔离，多租户边界为 `location`。

当前三个 Web 入口在部署主机上分别为：

| Web | 默认本机地址 | 用途 |
| --- | --- | --- |
| Trade Web | `http://127.0.0.1:18088/` | 注册、登录、行情、交易、资金、持仓 |
| Tenant Web | `http://127.0.0.1:18092/?location=<LOCATION>` | 租户管理员控制台 |
| Platform Web | `http://127.0.0.1:18090/` | 平台运营、租户审批/管理、集群管理 |

是否从公网直接开放这些端口由部署机防火墙、反向代理或 SSH 隧道策略决定；**当前仓库不要求固定使用旧的 `18089` 桌面隧道，也不把 `start-dc-saas-web.bat` 作为标准部署步骤。** 远程受保护环境应使用运维人员提供的 HTTPS/反向代理/SSH 映射地址。

- 业务数据：MySQL
- 行情与 K 线：ClickHouse
- 服务发现/集群协调：ZooKeeper
- 查询投影：ProjectionSvr（Order/Trade committed stream + durable watermark）
- 租户标识：`location`

> 当前版本仍属于功能、稳定性和生产化准备阶段，不应因自动验收通过就直接接入真实用户资金。页面“Deposit/充值”是测试环境内部记账，不是链上充值。

## 当前自动验收基线（2026-09-19）

安装、完整业务验收和卸载的标准命令为：

```bash
sudo ./install-saas.sh --full-cluster
sudo ./acceptance-saas.sh
sudo ./uninstall-saas.sh
```

`acceptance-saas.sh` 是当前统一验收入口。它会强制执行：

- 基础服务、数据库、端口、容器和 MD/Order/Trade 集群健康检查；
- Tenant/Platform 生命周期、双租户隔离和权限边界；
- 独立 Tenant Web `:18092` 当前所有已启用管理操作；
- 独立 Platform Web `:18090` 当前所有已启用管理操作；
- 真实注册、登录、测试入金、订单规则、Limit/Market/IOC、撤单、撮合、历史、余额、持仓和平仓；
- 部分/最终强平、保险基金、ADL；
- RobotSvr API Key、配置、10+10 报价、用户成交、补档、主动 sweep 和停报；
- Projection watermark 推进/不回退；
- TradeSvr A/B role reversal；
- **强制压力门禁**：默认 1,000 resting + mass cancel + 1,000 maker + 1,000 taker，并发 16，验证零请求失败/异步拒单、账务/保证金/持仓一致、重启恢复和无 OOM，并输出 TPS、p50/p95/p99；
- 最终再次执行全系统健康检查。

证据写入 `${DEPLOY_ROOT}/evidence/<run>-full-acceptance/`，最终汇总为 `acceptance-summary.json`。截至 2026-09-19，以上脚本、浏览器 E2E 和 CI wiring 已完成并通过仓库 CI；**真实 Linux/Docker 宿主机仍需实际运行一次该统一命令，才能把当前机器标记为全系统 PASS。**

2026-08-28 至 2026-09-01 的生产验证数据（包括 1000×16、3000×32、Robot、Web 和控制面）仍作为历史性能/稳定性证据保留，但不是当前操作入口或当前代码版本的运行结果。

## 1. 用户、租户与平台入口

### 1.1 交易用户登录

1. 从运营人员取得用户名、密码和所属 `location`。
2. 打开 Trade Web：

   ```text
   http://127.0.0.1:18088/#/login?location=<你的 location>
   ```

   如果部署在远程受保护主机，请使用运维提供的映射地址，不要假设固定为 `18089`。
3. 输入用户名和密码并登录。
4. 登录成功后进入交易页：

   ```text
   http://127.0.0.1:18088/#/trade?location=<你的 location>
   ```

不要修改或省略权威 `location`。订单、成交、持仓、余额、资金流水、行情订阅、路由键和服务端查询都以它作为租户边界。

Trade Web 业务会话通过 WebSocket 建立并恢复。页面刷新或网络重连时会使用已有 token 按 LoginSvr 协议恢复会话；密码不应写入浏览器持久化存储。

### 1.2 申请 SaaS 试用

公开申请页仍在 Trade Web：

```text
http://127.0.0.1:18088/#/apply
```

申请人填写组织、租户代码、联系人、邮箱、预计用户数、试用天数、交易品种等信息。平台运营通过 Platform Web 审批后创建 `location`、管理员、容量和交易品种。

### 1.3 租户内注册

当租户状态和“允许注册”开关允许时，可从 Trade Web 打开：

```text
http://127.0.0.1:18088/#/register?location=<你的 location>
```

注册成功后由后端创建真实用户 ID、账户及交易配置。用户名只要求在当前租户内唯一；不同租户可以同名，但用户 ID、密码、余额、订单、持仓和权限互相隔离。

### 1.4 租户管理员（独立 Tenant Web）

租户管理员当前标准入口：

```text
http://127.0.0.1:18092/?location=<你的 location>
```

Tenant Web 使用 `client_type=TenantAdmin` 登录，并要求 LoginSvr 会话返回的权威 `location` 与当前入口一致。当前已实现并纳入浏览器自动化的操作包括：

- 工作台；
- 用户列表、创建用户、启用/禁用、重置密码；
- 委托、成交、持仓、余额查询；
- 已分配品种列表及启用/禁用；
- Robot 列表、创建、编辑、启用/禁用；敏感密钥不明文回显；
- 租户基本信息、配额和只读服务集群信息；
- 审计日志；
- 注册/交易开关、默认语言和 Branding JSON 设置。

Tenant Web 请求链为 `Tenant Web -> HTTP -> GW -> AdminSvr`，后端以登录会话中的 `location` 作为权威边界。

### 1.5 平台运营（独立 Platform Web）

平台运营标准入口：

```text
http://127.0.0.1:18090/
```

当前已实现并纳入浏览器自动化的操作包括：

- 平台账号登录/退出；
- 租户申请列表以及“补充资料 / 拒绝 / 批准并开通”；
- 租户状态、名称、域名/Base URL、语言、试用时间、容量、品种和功能开关；
- OrderSvr/MDSvr/TradeSvr 租户路由策略；
- 集群拓扑、节点、分区、epoch、Desired Placement；
- Placement 配置校验/预览和 CAS 版本发布。

页面中的“新增节点 / 滚动升级 / 回滚版本”目前明确为 `AGENT REQUIRED`，按钮保持 disabled；在宿主机受限 Agent 实现之前，不应描述为可用功能。

## 2. 交易页布局

- 顶部：当前交易对、最新成交价、24 小时行情、标记价格、指数价格、资金费率及布局工具。
- 默认工作区：K 线图、订单簿/最近成交、下单、持仓/委托/成交、账户资产五个面板。
- 桌面宽屏默认采用专业永续合约布局；窄屏会按断点自动重排，字段和交易能力保持不变。

默认交易对为 `BTCUSDT`。点击左上角交易对可打开 Markets 抽屉；可使用中文/英文搜索框按交易对代码过滤，空结果会明确提示，选择交易对后抽屉自动关闭。

### 2.1 自定义工作区

1. 页面不设置单独的“编辑布局”模式。鼠标移到面板可拖动区域时会显示十字移动光标，按住即可拖动。
2. 鼠标移到面板右下角会出现缩放提示，按住即可改变宽度和高度，其他面板会自动避让和重排。
3. 单击右上角“恢复布局”可清除当前自定义布局并恢复默认排列。
4. 手机窄屏自动使用纵向布局，不要求用户手动编排面板。

布局按 `location + 用户` 保存在当前浏览器，刷新页面后继续生效；不同租户、用户和浏览器互不共享。如果清理浏览器站点数据，布局会恢复默认。

### 2.2 中英文切换

页面右上角提供“中文 / EN”切换。选择会保存在当前浏览器中，登录、行情、下单、订单、成交、持仓、资金和状态字段会随语言切换；`BTCUSDT`、`USDT`、`GTC/IOC/FOK/PostOnly` 等交易协议标识不翻译。

## 3. 添加测试资金

1. 在 `Account Info` 区域单击 `Deposit`。
2. 输入 USDT 数量。
3. 单击 `Confirm Deposit`。
4. 检查 `Total` 和 `Available` 是否增加。
5. 打开底部 `Funds` 页签，确认出现类型为 Deposit 的资金流水。

余额字段含义：

- `Total`：账户权益；当前余额加未实现盈亏。
- `Available`：可下单或提现的可用余额。
- `Position Margin`：持仓占用保证金。
- `Order Margin`：活动委托冻结的保证金和手续费。
- `Frozen`：其他冻结资金。
- `Unrealised PNL`：持仓未实现盈亏。

## 4. 下单

下单前确认交易对、方向、价格、数量和 `location` 均正确。

数量、限价和触发价必须为大于 0 的普通十进制数；输入为空、为 0 或为负数时，Web 会在请求发送前提示并阻止下单。交易精度、最小数量和最小名义金额仍以后端品种规则校验为最终依据。

### 4.1 限价单

1. 在 `Place Order` 中选择 `Limit`。
2. 输入 `Limit Price`。
3. 输入 `Amount`。
4. 做多单击 `Buy/Long`，做空单击 `Sell/Short`。
5. 未立即成交的订单会显示在 `Open Orders`。

系统按价格优先、同价时间优先进行撮合。买价达到或高于卖价时可以成交，实际成交价由撮合簿中的挂单决定。

### 4.2 市价单

1. 选择 `Market`。
2. 输入 `Amount`。
3. 选择 `Buy/Long` 或 `Sell/Short`。

市价单依赖当前租户、当前交易对的有效订单簿。系统不会在空盘口上报错成交；没有可成交盘口时，订单按 IOC 语义撤销未成交数量。市价单还受交易对的最大扫单偏离比例保护：当前 `BTCUSDT` 为 `5%`，买单不会成交到高于最优卖价 `5%` 的档位，卖单不会成交到低于最优买价 `5%` 的档位，超出保护边界的剩余数量自动撤销。

### 4.3 有效期和下单过滤器

- `GTC`：未立即成交的剩余数量继续挂单，直到成交或撤单。
- `IOC`：立即成交可成交数量，剩余数量自动撤销。
- `FOK`：必须立即全部成交，否则整单撤销且不产生部分成交。
- `Post Only`：只允许成为 Maker；如果下单时会立即成交，则整单拒绝。

每笔订单都会校验价格档位、数量档位、最小/最大数量、最小名义金额和交易对最大价格。Web 限价单可选择 `GTC`、`IOC`、`FOK` 或 `PostOnly`；市价单固定使用受价格保护的 `IOC`。

### 4.4 只减仓和平仓

持仓区域的平仓操作会提交 `reduceOnly` 市价单。只减仓订单只允许减少已有同方向仓位，不能反向开仓；当提交数量大于可平数量时，系统按可平数量自动缩量。重复使用同一客户端订单号提交完全相同的请求会返回原订单，参数不同则拒绝，避免网络重试造成重复下单。

### 4.5 条件限价单

1. 选择 `Limit Conditional`。
2. 输入触发价和数量。
3. 选择 `Last Price` 或 `Mark Price` 作为触发源。
4. 选择买入或卖出。

交易核心已具备 TP/SL 与 OCO 的基础触发和互斥语义；当前 Web 条件单入口仍需继续补齐追踪止损、Close on Trigger、回调率和完整保护单配置。

## 5. 撤单

1. 打开底部 `Open Orders`。
2. 找到目标交易对和订单。
3. 单击该行右侧 `Cancel`。
4. 撤单成功后，该订单从活动委托中消失，并在 `Order History` 中显示最终状态。

如果订单在撤单请求到达前已经完全成交，撤单可能被拒绝；应以成交回报和最终订单状态为准。

## 6. 查看成交和最近成交

- `Trade History`：仅显示当前用户的成交回报，包括数量、成交价、手续费、实现盈亏、订单号和成交号。
- `Order History`：显示订单完整生命周期，包括 `New`、`Partially_Filled`、`Filled`、`Canceled` 或拒单状态。
- `Recent Trades`：显示当前 `location`、当前交易对的市场最近成交，不是单个用户的私有成交记录。
- `Positions`：显示当前持仓、开仓均价、标记价格、保证金、强平价和盈亏。

常见状态：

- `Newing`：订单正在受理。
- `New`：订单已进入活动委托。
- `Partially_Filled`：部分成交，仍有剩余数量。
- `Filled`：全部成交。
- `Pending_Cancel`：撤单处理中。
- `Canceled`：已撤销。
- `Rejected`：订单校验或风险检查未通过；查看拒绝原因。

## 7. 当前限制

- 仅适合测试资金，尚未接入托管钱包、链上确认、提现审核和冷热钱包。
- 当前生产验证环境已能接收 Binance Futures ticker/bookTicker，并在 Web 显示 Last/Mark/Index；真实资金上线前仍需多源指数、异常剔除和断源降级。
- Robot 已完成内部 10+10 档报价、成交补档、价差内用户单主动成交和安全停报；真实 Binance 反向对冲未配置生产凭据，不能把内部流动性验收等同于外部对冲验收。
- 浏览器刷新和 WebSocket 真实断线后的无密码恢复已经通过生产验收；MySQL 原子轮换确保旧 token 只能消费一次，显式退出、用户失效、租户停用或跨 location 使用都会拒绝恢复。
- 隔离测试允许使用受控参考价；真实生产必须关闭任何“缺少标记价时回退到订单价”的测试开关。
- 已具备精度/数量/名义金额过滤器、`GTC/IOC/FOK/Post Only`、客户端订单号幂等、`reduceOnly`、市价扫单边界、STP、改单和批量撤单；仍需产品化断线全撤、完整双向仓位、全仓/逐仓保证金和更完整风险限额。
- 当前为单机 Docker 部署，没有达到真实资金要求的多可用区、高可用和灾备等级。
- 页面已支持中英文切换；少数后端协议枚举和品种/币种代码保持原始英文标识。

## 8. 使用安全

- 不要共享密码、会话令牌或未来创建的 API 密钥。
- 不要在公共电脑选择记住密码。
- 确认网址、`location` 和交易对后再操作。
- 遇到余额、订单或成交不一致时停止继续下单，记录订单号、成交号、时间和 `location`，由运营人员按 MySQL 订单/账本和服务日志核对。
