## Root bug corrected in the NEW Common path

The previous real `Trade OrderFacade.updateOrder()` invokes `TradeStateCoordinator.executeMutation()` and the original `CheckManager.updateOrder()`, where `ProcessOrder.checkOpen()` directly mutates real AccountBalance/Position **before** the post-factum state journal. In Common cluster mode, `executeMutation` deliberately fails closed. Switching off that guard would allow money mutation before signing a majority physical WAL.

T148 adds an explicit **Common-certified OPEN Newing ONLY** branch to the real `OrderFacade.updateOrder` when the service is in Common certified runtime. A new Spring `TradeCertifiedNewingAdmission` is constructed only with `trade.common.certifiedOpenNewing.enabled=true`; **OFF by default**. If the Common runtime is active without this certified Bean, or the incoming command is CLOSE/FILL/CANCEL/OTHER, `OrderFacade` throws `TRADE_COMMON_UNCERTIFIED_BUSINESS_PATH_DENIED`, not the legacy mutate-first path. Not a new election/replication implementation.

`CheckManager.prepareCertifiedOpenNewing` checks the *entire current configured validator census* prior to ANY checks: exactly one AccountBalanceCheck, SymbolCheck, MarkPxCheck, ReduceOnlyCheck, and the EXACT ProcessOrder class. Missing, duplicated, changed or unfamiliar checkers refuse the certified path (no skipping hidden check items). The four checked classes are read-only; the mutating ProcessOrder is replaced with the pure T147 `planOpenNewing()` that produces an immutable, fully domain-validated Trade StateBatch of AccountBalance, Position, OPEN_ORDER, DEDUPE_RESULT, with updated account-wide margin and correct original user/tenant/product. Insufficient funds returns the original risk rejection, no WAL or state write.

`TradeStateCoordinator.withCertifiedPartitionLock` serializes account/current shard observation, full validators, pure price/risk calculation, physical Common commit, and business apply. `TradeCertifiedNewingAdmission` freezes an immutable original ExecutionReport, checks exact original Newing fingerprint/terminal lifecycle, then calls existing Common `CertifiedBusinessCommandRegistry.commitThenApply()` **via** `TradeStateCoordinator.commitPreparedState()` for dual RSA WAL-fsync, signed CommitIndex, physically independent A/B Custody and receipts, and **only then** updates real `AccountBalanceFacade`, `PositionFacade`, `OrderManager`, and `ExecutionDeduplicator` from exact decoded Common WAL bytes. No success response is returned before certified apply. Common handles poisoning after a durable commit whose business application fails. Duplicate exact original request receives the old result without new commit; changed qty/price rejected before risk freeze.

The original complete `CheckManager.updateOrder()` and `ProcessOrder.checkOpen()` remain untouched for single-node legacy mode; no unsafe global bypass of `requireWritable`. When Common mode is enabled, OPEN Newing is routed ONLY through the new opt-in certification path; all other existing business commands remain fail-closed.
