## Actual source changes

`com.app.dc.service.check.ProcessOrder.planOpenNewing(ExecutionReport)` is a **pure domain risk calculator** derived directly from real `checkOpen` fields, data facades and formulas, not an artificial prefilled financial fixture. It validates `Newing + OPEN` and original tenant, user, order, product, side, strictly positive limit price/qty; fetches a real loaded balance and position, reads leverage, mark price, risk tier, taker fee, float margin, bankruptcy price; calculates frozen order volume and position fees, and the precise account-wide margin/commission delta. The original source account and position are JSON-cloned before planning; **no live object writes, DAO, business listeners or financial callbacks** occur. The output is a fully staged `TradeStateBatch` with AccountBalance, Position, OPEN_ORDER and DEDUPE_RESULT, including original Newing report and exact execution key, ready for the original `TradeStateCoordinator.commitPreparedState` Common-certified physical WAL path. Failed risk checks return no business mutation batch.

A discovered old risk check flaw was explicitly corrected in the **new pure planner only**: legacy `ProcessOrder.checkOpen` tests `balance - commission - adverse cost - floating risk` and does not cover the new frozen initial margin or prior other-product reserves. The new planner requires `balance - usedMargin - totalAFTERFrozenMargin - totalAFTERFrozenCommission - adverse cost - floatMargin >= 0`. This prevents a 1-USDT balance from preparing a leveraged order with a required 10-USDT initial margin. It retains exact side/mark/risk-tier checks. The existing live `checkOpen` is **not yet switched to the planner**; the current Common-cluster `TradeStateCoordinator.requireWritable` properly fails closed before old financial mutations.
