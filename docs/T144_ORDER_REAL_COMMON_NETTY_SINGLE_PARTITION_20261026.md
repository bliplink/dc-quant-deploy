## Verified code changes

1. `OrderStateJournal.record(...)` now ALWAYS fails closed in Common cluster mode even if a real physical Common writer is injected. The legacy callers previously modified `OrderManager`/order book and then persisted. A late signed WAL commit cannot make that earlier mutation atomic. `record()` remains a no-op only for the legacy non-cluster disabled runtime; old business endpoints are still blocked by `OrderClusterAdapter.recordCommand()`, `OrderStateJournal.requireStagedBeforeMutation()`, `beginSynchronousBatch()`.

3. `OrderStateRecovery.validate(...)` now rejects malicious nested `Order` identities that differ from the outer signed `OrderStateMutation` (location, security, market, order ID). This is enforced BEFORE the Common WAL append and again during replay.
4. New `OrderCommonSinglePartitionRealStateTest`: on `P090`, real `OrderManager`, `OrderStateRecovery` and real Order, actual signed Common physical CommitIndex, WAL/Custody, two existing RSA node identities A/B. Unit/integration tests cover signed UPSERT, signed REMOVE, restart reconstructing actual domain book via the exact committed journal payload, absence of replica certificate -> NO order apply, invalid nested tenant -> reject before fsync, domain apply crash AFTER signed commit -> poisoned writer/no customer ACK, and legacy post-mutate record refused even with physical Common writer.
5. Additional *actual TCP/Netty* P090 integration: instantiate Common `DirectNettyReplicationServer` and `DirectNettyCertifiedBusinessTransport` on loopback with separate A/B physical binary WAL, independently signed original RSA certificates and two physical custody receipts persisted on both nodes. Real `OrderJournalRecord` is signed/fsynced in both original WAL files, then applied to actual OrderManager; signed CANCEL also travels Common Netty and removes real order.
