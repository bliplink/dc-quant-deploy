# 可丢弃测试环境的全流程验证

目标是先跑通完整业务流程，遇到卡点修复后继续，必要时重新初始化测试环境。测试数据不备份；代码、安装配置/凭据、构建缓存保留。此入口仅适用于独立 dc-saas 测试环境，不适用于生产。

入口：`rebuild-test-saas.sh`。必须给出固定源码清单、专用构建目录、唯一 reset ID 和精确 runtime root；源码只从提交导出，不覆盖用户工作区。完整构建通过后才卸载与删除数据。可用 `--skip-build` 重用已核验的完整镜像集，但不能用缺项、失败、版本不一致或已换标签的镜像。

步骤：构建 11 Java + 3 Web → 普通卸载 → 精确删除组件数据（MySQL、ClickHouse、ZooKeeper 与本地交易/行情历史）→ 初始化数据库/控制面 → 创建无资金/订单/持仓的 Trade 本地空基线 → 安装服务 → API 初始化 → 300/16 业务验收。正常升级不触发空基线。测试流程不自动跳过失败，也不擅自重置其他系统。

初始化门禁：必须有本轮完整数据重置证明，两个 Trade 数据目录为空，256 条实际 ZK assignment 为 epoch1/version1/protocol3/dataVersion0，实际目录不含符号链接或嵌套挂载，没有业务进程/打开数据句柄。证明只可消费一次。部分初始化失败时需新的明确 reset ID 和重新清空，不能覆盖旧快照修补成 READY。

重置证明分别记录“实际删除的组件”和“本轮检查并确认已不存在的完整组件范围”，允许在已经清空的环境中重跑，不能误把本轮原本不存在的 Trade 目录当成未清理。测试 ZooKeeper CPU 配额由旧 0.10 调至 0.50：初始化期间实测持续打满旧配额，控制面命令与服务恢复都受限；交易节点配额本轮不改，TPS 需要按实际资源配置解释。

快照使用现用 v2、所有序列为 0、所有业务集合为空；通过实际 Trade 启动解析器校验。cash-v2 与 bounded recovery 的实验开关不强行开启。新资金通过正常 API，不从 Projection 数据补种本地状态。源码中仍有旧 DAO 写路径，需单列“Projection 独占写入”验收，不能把本轮流程通过解释为该目标已完成。

基础镜像仓库不可用时，可使用已经固定 ID 的本地 Node16/Node22 与 nginx 运行时；清除旧 Web 静态文件，再用固定源码及 package-lock 编译、安装新文件。详细基础 ID、依赖 JAR 哈希、镜像 ID 保存在构建证据。APS 的连接器依赖从独立固定源码清单构建，不依赖公开仓库恰好存在该版本。

本轮预验证：11 个 Java 服务 1152 项测试，0 failure/error，1 项可选数据库测试 skipped；DC Common 34 项、连接器 8 项、交易 Web 19 项；重置安全检查 8 项、空基线安全检查 7 项、assignment 迁移 3 项。它们不等于运行时业务、异常切换或 TPS 验收。

第一次完整重置暴露 ZooKeeper 双卷问题：`data/zookeeper` 是快照卷，`log/zookeeper` 是 `/datalog` 事务日志卷。只删前者会触发 “No snapshot found, but there are log entries”。重置工具已同时枚举两者，并在正常卸载、确认无句柄后删除；不会打开 trust.empty 掩盖丢失快照。另有精确 ClickHouse 日志目录随测试重置删除。新增第 9 项重置安全回归覆盖双卷。

测试日志按大小轮转，每个节点约 64 MiB 上限（16 MiB × 主文件与 3 份轮转），仍保留生命周期/恢复日志。测试安装容量门槛是至少 40 GiB runtime 空间，保留现有内存与 Docker 空间检查；不是生产容量规格。

第三次安装暴露固定端口与临时客户端端口冲突：Linux 临时端口范围 32768–60999，原保留清单为空，MDSvr 的 ClickHouse 客户端连接实际占用了本地 33038（远端 38123），Liq 因此无法绑定。部署现在在任何服务启动之前合并并持久化配置中的服务端口到 `ip_local_reserved_ports`，保留其他系统已有保留项。已有客户端连接不会被自动回收；本轮仅正常重启 MDSvr/Liq 后确认 33038 监听成功。该问题不是丢失 Trade 快照，也不应靠反复清数据解决。

现有 Trade assignment 的部署检查已显式传入 ZK SASL 客户端配置，避免第一次创建成功、再次部署读取失败。本轮续装实际检查 256 条、changes=0、主副 A/B 各 128，通过后进入默认 API 初始化。

续装已通过基础验证与默认 API 初始化，默认 E2E 机器人 RUNNING、20 档报价。后续业务验收发现两项独立问题：交易员 Key 用例把请求租户权限后的拒绝误判为失败，已拆分成“越权必须拒绝”和“合法 Key 必须成功”；Broker 客户 IOC 沿用 RobotSvr-Sweep 终端身份，正常客户挂单被机器人隔离规则跳过，已在 Robot 客户端区分 BrokerAPI / TraderAPI 与内部 RobotSvr 身份，不削弱原机器人隔离规则。Robot 修复提交 8360bc5，97 项测试通过，新固定镜像与全套版本清单见 `full-release-lock-20260930.json`。

测试生成环境显式保留日志限额与 ZK SASL 客户端设置，续装不应把日志改回无大小上限；日志配置支持仅热更新，无需为限额重启交易服务。完整业务/异常切换/TPS 结果必须以之后实际验收证据为准，上述启动与单测结果不可代替。

进一步 Web 验收发现原固定 Trade Web 提交 `ee3935e` 尚未提交租户入口 `/tenant`：Nginx 健康检查通过，但浏览器是空白页。已改用已有完整提交 `1ca247a` 构建新 Trade Web 镜像，浏览器确认租户入口实际渲染。控制台实际为独立 Tenant Web / Platform Web 服务，验收脚本据此分别检查交易站公开租户入口与两个独立控制台，不再对交易站虚构 `/tenant-admin` 页面。页面自动化中的文本定位须唯一，避免同一行状态标签和表格单元格重复时误报失败。
