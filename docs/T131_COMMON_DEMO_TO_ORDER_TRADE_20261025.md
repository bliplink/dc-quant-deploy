## Critical architectural blockers: do not declare Order/Trade READY yet

1. **Actual deployment is still OLD cluster configuration.** `dc-saas-runtime-clean-20261016/control/overrides/OrderSvrA/config/application.properties` contains 50 `order.cluster.*` keys and zero `order.common.*`; Trade equivalent has 83 `trade.cluster.*` and zero `trade.common.*`. Old `lifecycle.enabled`, `failover.enabled`, and `replication.enabled` remain true. Do not deploy the T131 candidate using those files: it would exercise legacy cluster controls, not the Common HA proven on Demo. The old `ServerGwWrapper` starts legacy ZK service coordination before Spring, which must be neutralized/retired separately without breaking GW message transport.
2. **Physical-proof/lease bootstrapping is incomplete in Spring.** The Order/Trade `*CommonNodeRuntimeWiring` factories call `CommonCertifiedNodeBootstrap.openAndStartWithZkFencing`, which demands an authenticated actual ZooKeeper node grant and signed durable physical evidence. Existing `*CommonPhysicalProofWiring` requires a genuine `CertifiedPersistedCustodySource` bean; business services do NOT yet install it or an exact recovery request + durable business baseline. No unsigned genesis shortcut is allowed.
3. **PREPARING/RECOVERING is a distinct Common phase.** `CommonCertifiedNodeBootstrap` requires routable READY and rejects PREPARING/RECOVERING. Common already has separate `CommonRecoveringNodeRuntime` with authenticated recovery-only read/control RPC, NEVER a business ACK. Wire it as the recovery phase and transition to certified business runtime only after signed state replay + external READY. Do not relax READY checks.
4. **Atomic Order/Trade mutation integration is not complete.** Order `OrderStateJournal.beginSynchronousBatch`, `OrderStateJournal.requireStagedBeforeMutation` and `OrderClusterAdapter.recordCommand` intentionally fail closed; Trade `TradeStateCoordinator.requireWritable` intentionally denies before business mutation. These must become Common-only authenticated commit-before-domain-apply transactions with deterministic domain WAL replay; never simply delete the denial or treat post-mutation journaling as atomic. `OrderRecoveryStateMachine` currently accepts only valid `STATE_*` deltas; precommitted raw commands must not be fed into it without a new checked replay codec.
5. **Common E2 local mode must be exercised on formal node.** A normal strict `CommonCertifiedNodeRuntime` expects RF2 STRICT, while Demo's post-failure writing uses Common `CommonCertifiedDegradedPrimary` with external C-signed `LOCAL_DURABLE_ASYNC` policy. Order/Trade need a Common-controlled phase dispatcher for strict READY/recovering/local degraded and exact business restart replay. Never report degraded local customer ACK as quorum.
6. Demo test topology resides on one Mac; production cross-host fencing and 256 partition/10,50,200 tenant consistency, orders/executions/balances/positions/Projection watermark remain NO-GO.
