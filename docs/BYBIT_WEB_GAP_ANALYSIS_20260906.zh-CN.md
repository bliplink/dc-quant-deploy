# DC SaaS 永续合约交易页与 Bybit 功能差距及实施清单

日期：2026-09-06  
范围：`dc-trade-web` 交易页、GW、OrderSvr、TradeSvr、MDSvr、LiqSvr 及租户交易配置  
基准：Bybit USDT 永续合约交易页及 Bybit 官方帮助中心当前公开规则

## 1. 结论

当前系统已经具备永续合约交易台的基础骨架：公开行情、历史与实时 K 线、盘口、最近成交、登录后下单、持仓、活动委托、委托历史、成交历史、资金流水，以及限价、市价、条件单、TIF 和只减仓等基础能力。

与可生产使用的 Bybit 类永续合约交易台相比，最重要的缺口不是页面样式，而是下列交易闭环：

1. 全仓/逐仓切换及已有仓位的保证金一致性处理。
2. 杠杆设置、风险限额校验，以及保证金/强平价的同步重算。
3. 单向持仓/双向持仓模式，并禁止在存在活动委托或持仓时非法切换。
4. 下单时预设止盈止损，持仓后修改/取消止盈止损。
5. 按数量、价值、成本下单和 0/25/50/75/100% 滑杆。
6. 按数量或百分比市价/限价平仓、反向开仓、全部平仓。
7. 活动委托改单、批量撤单，以及完整的订单属性展示。
8. 维持保证金率、风险限额、预估强平价、预估手续费等下单前风险信息。

因此建议先做 P0 的后端规则收口，再同步交付前端控件；不能只在 Web 中增加“全仓”“10x”等展示文字。

## 2. 当前页面已有能力

| 区域 | 当前能力 | 结论 |
| --- | --- | --- |
| 行情头 | 最新价、涨跌、高低、标记价、指数价、资金费率、成交量 | 已有基础能力 |
| 图表 | TradingView 历史 K 线及 WebSocket 实时更新 | 已有；继续验证长时间增量更新 |
| 盘口 | 买卖档位、累计数量、深度背景、最新价/标记价 | 已有；Robot 报价链路需继续稳定性验收 |
| 下单 | 限价、市价、条件单、GTC/IOC/FOK/PO、只减仓 | 基础可用，但缺保证金模式、杠杆、仓位模式、TP/SL 和下单测算 |
| 持仓 | 数量、开仓价、标记价、强平价、保证金、盈亏 | 基础展示；仅支持整仓市价关闭，操作能力不足 |
| 委托 | 活动委托、委托历史、成交历史、资金流水 | 已有；活动委托缺改单/批量撤单及若干交易属性 |

## 3. P0：上线前必须补齐

### P0-1 全仓/逐仓

前端：

- 下单区顶部显示当前品种保证金模式，点击打开确认弹窗。
- 持仓行显示保证金模式。
- 逐仓持仓提供增加/减少保证金入口；全仓不显示该入口。
- 切换后立即刷新可用余额、占用保证金、维持保证金和强平价。

后端：

- TradeSvr 已有 `setPositionType` 和 `Cross/Isolated` 数据模型，但必须补齐权威的 `getSymbolConfig` 查询。
- 明确并实现切换规则：存在活动委托时禁止切换；存在持仓时，第一版建议禁止切换，后续再实现带事务的保证金迁移。
- 逐仓保证金必须独立记账，不能只修改 `dc_users_symbol_config.position_type`。
- LiqSvr/RiskEngine 必须以成交时固化的仓位模式计算维持保证金、破产价和强平价。

验收：并发下单期间无法切换；切换失败不改变数据库配置；成功切换后 Web、TradeSvr、LiqSvr 三方结果一致。

### P0-2 杠杆设置

前端：

- 下单区顶部显示 `10.00x` 等当前杠杆，支持输入和滑杆。
- 显示该租户/品种风险档位允许的最大杠杆，而不是固定 1-100x。
- 修改前显示新的起始保证金、维持保证金及预估强平价。

后端：

- TradeSvr 已有 `setLeverage`，但需补 `getSymbolConfig`，并让设置接口校验租户品种、风险档位和最大名义价值。
- 无持仓时可直接保存；有持仓时必须事务内校验可用余额并重算保证金/强平价，失败整体回滚。
- 新订单和已有持仓必须使用同一份权威杠杆配置；禁止客户端在订单中伪造杠杆。

验收：越界杠杆拒绝；有仓调低杠杆且余额不足时拒绝；重连后展示值与服务端一致；强平测试使用修改后的杠杆。

### P0-3 单向/双向持仓模式

前端：

- 账户级配置中提供单向持仓和双向持仓。
- 单向模式继续使用买入/做多、卖出/做空语义。
- 双向模式明确区分 `OPEN/CLOSE` 与 `LONG/SHORT`，持仓表分别显示多仓和空仓。

后端：

- TradeSvr 已有 `getAccountConfig/setAccountConfig` 和 `positionWayType`。
- 增加活动委托检查；只有“无持仓且无活动委托”时才允许切换。
- OrderSvr 对 `PositionSide`、`OCType`、`ReduceOnly` 做组合校验，防止双向模式下误平另一侧仓位。

验收：有仓或有单切换必失败；双向模式可同时持有多空；只减仓不会反向开仓。

### P0-4 完整止盈止损

前端：

- 限价/市价下单可选预设止盈和止损。
- 支持按最新价、标记价触发；补齐指数价触发后再开放该选项。
- 持仓行可新增、修改、取消整仓 TP/SL；第一版不开放“部分仓位 TP/SL”。

后端：

- OrderSvr 已支持 `TakeProfitPrice/StopLossPrice` 及条件单生成，前端尚未接入。
- 必须补齐触发单与仓位生命周期绑定：仓位减为零时撤销剩余保护单，仓位减少时保护数量不得超过可平数量。
- 标记价、最新价触发源由 MDSvr/OrderSvr 权威判定，客户端只提交选择。

验收：开仓成交后自动生成保护单；触发后只减仓；重复行情不重复触发；手工平仓后保护单自动撤销。

### P0-5 下单金额与风险预览

前端：

- 数量单位支持 BTC、订单价值 USDT、订单成本 USDT。
- 增加 0/25/50/75/100% 滑杆。
- 展示可开数量、订单价值、预估保证金、预估手续费和预估强平价。
- 市价单显示滑点提示；条件单显示触发方向和触发依据。

后端：

- 增加只读预检查接口，复用实际下单的精度、最小数量、最小名义价值、价格保护、余额和风险限额规则。
- 预检查结果仅用于展示；实际 `placeOrder` 必须再次权威校验，不能信任前端计算。

### P0-6 平仓、改单与批量撤单

前端：

- 持仓平仓弹窗支持市价/限价和数量/百分比，不再只有整仓市价关闭。
- 增加“全部平仓”，必须二次确认。
- 活动委托支持修改价格/数量、单条撤销和按品种批量撤销。
- 活动委托补充 TIF、只减仓、触发价类型、仓位方向和创建时间。

后端：

- OrderSvr 已有 `replaceOrder` 和 `cancelAllOrder`，前端尚未形成闭环。
- 批量动作必须由服务端会话限定 location/user，不接受客户端越权身份字段。
- 平仓数量以 TradeSvr 权威可平数量为准，所有平仓单强制 `ReduceOnly=true`。

## 4. P1：专业交易体验

| 功能 | 说明 | 主要服务 |
| --- | --- | --- |
| 部分仓位 TP/SL | 多组止盈止损、按数量或比例设置 | Web、OrderSvr、TradeSvr |
| 追踪止损 | 激活价、回撤距离/比例、标记价或最新价触发 | Web、OrderSvr、MDSvr |
| 反向开仓 | 原仓平掉后按剩余数量反向开仓，必须定义失败原子性 | Web、OrderSvr、TradeSvr |
| 逐仓保证金调整 | 增加/减少保证金并实时更新强平价 | Web、TradeSvr、LiqSvr |
| 风险限额 | 风险档位、维持保证金率、最大仓位和最大杠杆展示/调整 | Web、ManageSvr、TradeSvr、LiqSvr |
| 合约资料 | tick、数量步长、最小名义价值、费用率、资金周期、风险参数 | Web、AdminSvr/ManageSvr |
| 合约计算器 | 盈亏、目标价格、强平价计算 | Web，结果须与 TradeSvr 公式一致 |
| 图表交易标记 | 委托、成交、持仓成本、TP/SL 线及拖动改单 | Web、OrderSvr、MDSvr |
| 通知 | 成交、撤单、强平、资金费、风控拒单通知 | GW、各业务服务、Web |
| 收藏与品种切换 | 收藏、最近访问、24h 行情排序 | Web、MDSvr |

## 5. P2：暂不作为首发阻塞项

- 多图表和更高级的 TradingView 布局。
- TWAP、冰山、分层/拆分订单等算法单。
- 快捷键、分享盈亏图、个性化通知。
- 组合保证金。组合保证金会改变账户级风险模型，不应作为普通的第三种下拉选项直接加入。

## 6. 移动端差距

当前响应式堆叠只能保证页面可打开，尚不足以称为生产移动交易页面。建议提供独立的移动交互：

1. 行情、图表、盘口、成交使用顶部标签切换，避免纵向无限堆叠。
2. 底部固定“买入/做多”“卖出/做空”，点击后从底部弹出完整下单面板。
3. 持仓/委托使用可左右滑动的紧凑卡片，关键操作固定可见。
4. 盘口价格可触控回填，数量滑杆适配触控，危险操作二次确认。
5. 断线、重连、会话失效和行情陈旧必须有明显状态提示。

## 7. 推荐实施顺序

1. TradeSvr 增加权威品种配置查询，补齐杠杆/保证金模式/持仓模式的切换约束和事务规则。
2. OrderSvr 补齐持仓模式组合校验，并把预设 TP/SL、改单、批量撤单纳入端到端测试。
3. Web 第一批接入全仓/逐仓、杠杆、单向/双向、数量滑杆和风险预览。
4. Web 第二批接入持仓 TP/SL、部分平仓、全部平仓、改单和批量撤单。
5. LiqSvr 做各模式、各杠杆的强平回归；MDSvr 验证标记价触发和实时行情。
6. 完成桌面端、移动端、断线重连、并发和跨租户权限验收后再开放给租户。

## 8. 上线门槛

- 所有配置写接口均以 GW 会话中的 location/user 为权威身份。
- 杠杆、保证金模式或持仓模式更新不得出现“数据库成功、内存失败”或相反情况。
- Web 展示的仓位、保证金、强平价和 TradeSvr/LiqSvr 查询结果一致。
- 有仓/有单非法切换、只减仓反向开仓、保护单超量等负面场景全部有自动化用例。
- 桌面与移动页面均完成真实 WebSocket 行情、下单、成交、撤单、平仓和重连验收。
- Robot 持续报价和混合用户交易期间，Web 可见盘口连续，后台无长期锁定的部分成交残单。
