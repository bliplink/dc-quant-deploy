# 现金原结果持久去重与恢复：候选验证

日期：2026-09-29。Trade 本地提交 `40ae10c`；Projection 隔离协议拒绝测试 `d4cd054`，说明文档 `cc1694f`。这是本地候选切片，不是线上现金幂等、自动切主或 TPS 验收。

## 本轮完成

- 在现金计算之前即可按明确的客户端操作 ID、已认证 location/user、服务端账户模式生成身份和请求指纹。同 ID 改方向、金额、币种、账户或附加内容拒绝；数值等价的绝对金额保持一致。不把 session、随机 eventId、节点或 epoch 当业务操作身份；拒绝会导致 UTF-8 哈希别名的非法 Unicode。
- 将首次完整成功结果冻结为 JSON，与余额后态、不可变 POSTING 一起写入新的三 mutation 候选批次。验证结果的请求/租户/用户/余额/保证金/状态与待提交后态一致；保留结果额外字段，不用当前余额重拼旧结果。
- 候选去重索引保存不可变记录，查重只读固定身份/指纹和原结果。新提交坐标重复出现同一现金身份会失败，不能把它当新的资金效果；恢复替换本分区记录时保留其他分区身份。
- 使用真实的**合成 Chronicle 日志**验证关闭、重开、已提交但未安装/响应、快照＋增量、未提交尾、重复/部分批次、缺少索引、容量不足及过期 epoch。账户已到 120 时，第一笔重试索引仍返回首次 110；恢复不执行现金计算、DAO 或发布。
- 新快照包含完整原结果、数量与绑定分区/epoch/提交坐标的 SHA-256 清单；缺失/改动记录或清单会在余额安装前失败。清单仅用于意外损坏/遗漏检测，不是签名、业务正确性或 RPO=0 证明。
- 快照捕获要求索引已成功恢复到当前 assignment epoch 和 committed-state 坐标。空/落后的索引不能覆盖正确快照；低级 `installCommitted` 会撤销覆盖证明，未来必须接入真实坐标感知的提交/安装适配器。

## 格式与容量门禁

新三 mutation 批次使用 **STATE_BATCH version 2**；缺少必需原结果不能被当作旧现金批次恢复。旧 version 1 路径保持兼容，但没有客户端操作 ID 的旧历史不会自动获得幂等。

现金快照使用 **version 3**，必需原结果段、数量、清单；旧 version 2 不能编码现金去重状态。无候选索引的恢复器拒绝 version 3，快照管理器拒绝降级覆盖；旧二进制拒绝新版本，不可混合上线。

候选硬上限：每节点 10,000 条，序列化记录合计 16 MiB，单条 64 KiB；可设更小限制，不可绕过快照硬上限。它不是精确堆配额，也不是生产长期留存方案。容量耗尽拒绝新记录，没有 expiry/LRU/delete，不删除或修剪 journal。恢复计数增量累加，查重与归属过滤不反复解析/哈希所有记录；尚未量测生产恢复时延或 TPS。
