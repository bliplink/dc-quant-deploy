# 新现金格式消费者：默认关闭的投影候选验收

日期：2026-09-29。Projection 本地提交 `3122a8d0ab94d5e7a4e177951b2e4ed5ee58d38d`；与 Trade `64acf8e` 的候选生产器/原结果协议配合。此前“当前消费者只拒绝 v2”的描述属于上一切片及仍未改变的运行环境；**新源码候选可在显式启用时消费 v2，默认仍关闭，线上未升级**。

## 本轮补齐

- 增加 `projection.trade.cashRequestV2.enabled=false`，必须同时启用 core/posting 物化才允许初始化。没有修改线上配置、镜像、现金入口或旧 Trade SQL 写入方；关闭时仍整事务拒绝 v2。
- 校验完整三效果批次：余额、不可变流水、首次成功结果；校验版本/操作/租户/用户/请求身份、稳定流水 ID、金额规范、方向与所有附加字段的请求指纹、冻结流水 payload，以及完整标准余额报告字段与提交后态一致。缺少/重复效果、同 ID 内容冲突、坏结果或越界金额拒绝。
- 首次完整结果 JSON 与冻结流水 JSON 原样保存到新查询投影表 `dc_trade_projection_cash_request`；不根据当前 SQL 余额重拼原结果。新余额变化后，旧请求仍是旧首次结果。
- 结果采用普通 INSERT，与余额、流水、事件/变更归档、watermark 在一个事务内提交。相同提交坐标的传输重复按 watermark 跳过；同业务操作在另一个坐标或分区再次出现时整事务失败，不能覆盖原结果/流水或再次安装余额。
- 新结果表检查 InnoDB、完整 `(location,user_id,request_id)` 主/唯一键、禁止前缀唯一键、字段类型/容量/非空与二进制 UTF-8 比较。现金模式还检查余额身份大小写精确、余额十进制精度和流水文本容量/编码。既有不兼容业务表只拒绝，**不自动 ALTER**。
- 输入存在非法 UTF-8 时拒绝，而不是替换字节后保存“原结果”；此检查也适用于新收到的 v1 payload，合法旧 UTF-8 保持兼容。

新表始终是**可重建的查询投影，不是核心恢复或请求去重权威**。Trade 权威仍在本地快照＋已提交 journal＋原结果索引，核心不从这个表恢复。既有余额查询表只物化已有 schema 支持的余额/保证金字段；完整冻结余额、模式/账户状态与其他字段保留在 mutation/原结果中，不代表所有查询字段都已单独物化或账务对账完成。

## 实测验证

Projection 全量离线 Java 8：**12 类 / 73 项**，新增协议/编码/结构门禁 **17 项**，无 failure/error/skip。Trade 未改源码，重新执行全量 **64 类 / 295 项**通过。

MySQL 8.0.36 合成隔离用例最终 **45 项连续 3 轮 PASS**：原 27 项（包含关闭时拒绝新格式）＋18 项启用候选测试。实际调用当前编译的 Trade 构造器和原结果类，账户/产品/币种/info1..5 均填值，并带中文/emoji，避免仅测全空指纹。三轮消费者、校验器、测试器、生产器和依赖摘要一致。

覆盖入金/出金物化、8 路并发传输重复、余额变化后原结果保留、跨坐标/分区重复操作、结果唯一约束冲突、坏结果/UTF-8、wire 批次后续事件失败、结果 SQL 失败、SQL 提交确认丢失、消费者对象重新创建与重放、大小写/Unicode 身份隔离、引擎/键/比较规则/字段容量/精度门禁。

结果唯一约束用例只在隔离 DB 人工放置一条结果投影，以独立验证结果约束失败能回滚此前余额/流水/归档；它**不是合法历史导入基线**。重建消费者对象不等于进程退出、数据库重启、线上 GAP 网络演练或自动切主。

报告与摘要：[机器可读证据](evidence/trade-cash-v2-projection-candidate-20260929.json)。临时 MySQL 无外网/宿主端口/线上配置或数据挂载，只使用 tmpfs；按准确容器 ID 与 ownership label 清理，最终无残留，报告保留。8 个核心容器只读检查仍为原镜像、running、restart=0、OOM=false，不证明业务可写或 HA。

## 仍不能启用生产写入

1. 明确现金 API 操作 ID、已认证租户/用户绑定和旧客户端兼容，落实真实准入/风险策略。候选回调和纯构造器不是完整线上入口。
2. 为混合非现金交易推进候选索引的覆盖坐标，验证全节点冷恢复/admission 容量、重试窗口、持久冷请求/流水留存。当前混合业务会安全拒绝，不能直接接线。
3. 验证实际数据库全部 schema、编码/SQL mode/触发器、归档字段容量及已有大小写碰撞；本轮检查不是完整线上数据库资格证明。需要单独审批和演练的迁移，不让启动过程自行改既有身份规则。
4. 做 Projection GAP 拉取/追平、全历史重建及财务对账，定义推送遗漏/重复的投递契约。核心发布仍不是 durable outbox，DB 物化 PASS 不证明业务订阅收敛。
5. 可信历史配置/账务基线、funding/保险/ADL 文件权威和旧 SQL 写入方退场仍未完成。不能同时开启候选物化与旧 writer 双写，也不能自动用 Projection 数据补权威基线。
6. 公共 Order/Trade/MD 恢复适配、大分区接管容量、受控异常与业务重试门禁通过后，再量测 300/16、分级 TPS 和长稳。本轮没有 TCP 复制、进程强杀、promotion、RPO/RTO/TPS 或跨宿主机 HA 验收。
